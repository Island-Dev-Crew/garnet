Methodology

The per-slice loop

Every phase was a single, narrow, evidence-backed slice confined to apps/garnet-studio, branched from a fresh origin/main. The same pipeline ran each time and auto-iterated to the next phase on merge.

01

Red tests first

TDD: failing tests pin the contract before any behaviour change.

02

Implement the slice

Typed backend + a pure, testable renderer module; CLI rendered verbatim.

03

7-pass review

14 agents (7 passes × Judge + Auditor) adversarially verify against the code.

04

Fix + ladder

Apply findings; run fmt · clippy · crate · build · e2e · contracts · smoke.

05

Focused PR

Dogfood-readiness body; cross-repo PR from the fork to IDC.

06

CI-green merge

Browser squash-merge on IDC once every check passes; sync main; iterate.

The spine

Calibrated honesty, upheld

The whole point of the redesign: the Studio is a faithful window onto the trust spine, never an embellishment of it.

CLI is the source of truth

Verdicts, bands, diagnostics, and decisions are the CLI's own — rendered verbatim, never recomputed in the UI. Pure renderer modules make that testable.

Enforced ≠ declared

"Enforced" appears only where a deterministic trap is proven by test — @caps + @max_depth. Bounded / memory / time / mailbox / OS-sandbox render as declared or deferred.

No false greens

Across phases the reviews killed every "looks-clean-but-isn't" path: green gated on real success, strict JSON, confirmed-only badges, verdict-from-decision.

Integrity rules intact

No slice modified the gate it merged under; no capability widening; every autonomous merge records agent / model / gate-version. The release tag stays Jon's.

Scope held the line. Every shipped slice stayed inside apps/garnet-studio (non-frozen), added no new crate dependency and no capability surface (core:default), and changed no script, CI gate, dogfood probe, or frozen crate. Work that would have touched a CI gate — the stale Release-tiles removal — was parked as human-merge-only rather than forced through.

Provenance. Phases 0–5 merged on island-dev-crew/garnet main via browser squash-merge (PRs #427–#432), each authored from the fork and gated on full remote CI. Auto-iteration continued in perpetuity to the end of Phase 5.
Boundaries. Garnet remains a research-grade prototype (v0.x.x), not production / 1.0. The cut act and release tags are Jon-owned — no tag was pushed autonomously.
Companion ledgers. Per-phase detail lives in CHANGELOG.md (same-PR entries) and the merged PR bodies' dogfood-readiness sections.
