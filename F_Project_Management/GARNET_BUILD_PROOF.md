# Garnet build proof — Windows / Linux / macOS (S47)

The reconciliation's Windows-propriety question (§148-149): *does every attribute
behave correctly cross-platform, or is it just packaging?* This document answers
it from the CI matrix and audits the platform-sensitive surfaces. The live table
is regenerated by `scripts/garnet_build_proof.py --format md`; the
`--gate` form runs in CI and fails if cross-OS test coverage regresses.

## Two axes, kept distinct

- **behaves** — the OS is in the `cargo test --workspace` matrix in
  `.github/workflows/ci.yml` (`os: [ubuntu-latest, windows-latest,
  macos-latest]`). The toolchain compiles **and** the full test suite passes on
  that OS. This is the substantive proof.
- **distributes** — a packaging artifact exists for that OS family
  (`linux-packages.yml`: deb/rpm smoke + `macos-cli-tarballs`). The "just
  packaging" axis; absence is reported, not gated.

| OS      | behaves | distributes |
|---------|---------|-------------|
| Linux   | ✅ `cargo test --workspace` (ubuntu-latest) | ✅ deb/rpm smoke |
| Windows | ✅ `cargo test --workspace` (windows-latest) | — (CLI packaging not yet wired; the Windows **Studio** installer is tracked separately) |
| macOS   | ✅ `cargo test --workspace` (macos-latest) | ✅ macos-cli-tarballs (aarch64 + x86_64) |

**All three target OSes behave.** The build-proof gate (`garnet_build_proof.py
--gate`, wired into the `agent-contracts` CI job) prevents an OS being silently
dropped from the test matrix.

## Honest scope

- **CI-attested, not locally re-run.** Development happens on a single OS; the
  cross-OS execution is proven by CI, and this slice gates that the matrix
  *covers* all three — it does not itself run Windows/Linux.
- **"Build proof" = builds + workspace tests pass per OS.** It is not a claim of
  exhaustive feature parity; the audit below lists known platform-sensitive
  surfaces and their status.
- No Windows CLI distribution artifact exists yet (only the separate Studio
  installer). That gap is reported, not hidden.

## Windows-propriety audit — platform-sensitive surfaces

| Surface | Cross-platform status |
|---|---|
| Pure language/runtime logic (parser, check, interp, vm) | **CI-gated** — `cargo test --workspace` passes on all three OSes. |
| Determinism (output byte-stability) | **CI-gated** independently by `determinism.yml` (Cross-OS determinism). |
| S46 sandbox policy (seccomp) | **Documented gap** — the seccomp profile is Linux-syscall-shaped. `garnet sandbox` *generates* it on every OS, but it is only meaningful for a Linux enforcement host (and S46 enforces nothing anywhere — generation only). |
| Filesystem paths / separators | **CI-gated** via the workspace tests (registry vendor, cache, manifest paths exercised on all three OSes). |
| Line endings in generated artifacts | **Documented** — hand-rolled JSON/markdown writers emit `\n`; not normalized to CRLF on Windows (intentional, keeps determinism). |
| Terminal/markdown output | **Documented** — ANSI/UTF-8 assumed; no Windows-console-specific handling claimed. |
| Windows CLI distribution | **Deferred** — no winget/MSI for the CLI yet (Studio installer is separate). |

## Regenerating

```sh
python3 scripts/garnet_build_proof.py --format md   # this table
python3 scripts/garnet_build_proof.py --gate        # CI coverage gate (exit 1 if an OS is dropped)
```
