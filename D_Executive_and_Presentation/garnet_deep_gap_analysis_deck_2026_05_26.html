C++ interview filter

Problem first. Foundation before features.

  • Do not start with "we built a language"; start with the problem existing languages cannot make explicit enough.
  • Keep high-level orchestration and low-level/native boundaries in one architecture, without pretending one mode owns every job.
  • Do not add a second gun deck without reinforcing the hull: stdlib growth needs CapCaps, stability, tests, docs, and dogfood.
  • Use standards discipline early: governance, RFC shape, and compatibility promises prevent dialect drift.
  • Claim zero/negative overhead only where the VM/native backend can prove it.
Bjarne's lesson maps cleanly to Garnet: solve the real problem and keep the proof honest.
