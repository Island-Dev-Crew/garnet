Stdlib Primitive Registry

The current registry exposes 80 primitive entries. Pure helpers need no capability; time, filesystem, network, environment and process primitives declare one. Only the 15 entry-gated rows are refused at run time when the program entry does not declare their capability; checker-only rows are checked by garnet check and not gated at run time; unbridged rows have no interpreter binding.

This is a registry reference, not a promise of a mature standard library. Higher-level HTTP, package, async, and data APIs remain future library work.

What Is Still Missing

A production-feeling language needs more than this registry. The next useful layers are HTTP client/server helpers, datetime, configuration, package manifests, and richer test helpers; JSON, regex, UUID, base64 and logging already have registry rows above. Those should land behind the same capability discipline, with examples and dogfood evidence beside the implementation.
