Converter fit is decided by parser certainty and memory/capability preservation:

  • Active lanes only enter deterministic mode when parser, lowering, migration check, and evidence output are proven in local checks.
  • Advisory lanes are useful for migration planning, but not source replacement, until deterministic frontend support and dogfood gates are in place.
  • Native-boundary lanes preserve ABI, platform, and performance contracts; they stay native modules/FFI unless a backend lowering strategy changes the guarantee surface.

LLM Advisory Pipeline

Provider-backed conversion is not active. The feasibility reporter now exposes ten provider options as advisory-only evaluation candidates, and Garnet Studio can preserve that registry as a Desktop dogfood evidence bundle with source omitted by default and human approval required. The approved pipeline is:

source classifier -> risk inventory -> Garnet context -> advisory plan -> review handoff -> human-approved candidate -> garnet check/test/dogfood

  • Do not execute source during analysis.
  • Do not include source text in provider packets by default.
  • Require lineage, sandboxing, migrate_todo, `garnet check`, dogfood evidence, and human audit before trust.
  • Keep deterministic converter output authoritative where deterministic support exists.
